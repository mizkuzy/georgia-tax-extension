# ADR 0001: Расширение Chrome для ежемесячной декларации малого бизнеса (Грузия)

**Статус:** принято
**Дата:** 2026-10-02
**Источник требований:** `REQUIREMENTS.draft.md` (источник правды)

## Контекст

Каждый месяц до 15 числа нужно подать декларацию «Small business annual income» на https://eservices.rs.ge/, даже если нет дохода. Доход приходит в USD, в декларации указывается в GEL по курсу NBG на дату получения. API у RS нет — работа только через страницу.

## Решение

### Форма приложения

Расширение Chrome. Установка: «Загрузить распакованное» из папки проекта.

Язык: JavaScript без сборки. Без TypeScript, фреймворков и зависимостей. Папка проекта загружается в Chrome как есть.

Почему не скрипт Playwright: скрипт запускается из терминала и открывает отдельный браузер. Расширение работает в обычном Chrome, где пользователь уже залогинен.

### Сценарий

Пользователь сам логинится на eservices.rs.ge и нажимает на иконку расширения. Дальше всё делает расширение. Пользователь ничего не нажимает на сайте, только вводит данные в расширении и в конце отправляет декларацию.

1. **Проверка при запуске** (и кнопка «Проверить снова»). Только проверка, без переходов и кликов: активная вкладка — eservices.rs.ge или decl.rs.ge, не страница входа. Иначе — ошибка, кнопка «Заполнить» неактивна.
2. **Ввод данных.** Расширение спрашивает дату и сумму в USD. Дата предзаполнена: 22 число предыдущего месяца. Пользователь может её изменить, но только в пределах предыдущего месяца: декларация подаётся за прошлый месяц. Другая дата — ошибка. На RS ничего не меняется.
3. **Курс.** Расширение получает курс NBG на эту дату, считает GEL и налог 1%. Если NBG не ответил — ошибка и остановка.
4. **Страница деклараций и декларации за месяц.** Расширение открывает страницу деклараций через вход `https://eservices.rs.ge/Redirect.ashx?Module=DECL`, переключает её на английский и проверяет, что пользователь залогинен. Декларации за месяц расширение узнаёт запросом к сайту (`get_grid_r_data`), без кликов.
5. **Вопросы, потом клики.** Пока не получены все ответы, на сайте ничего не нажимается.
   - Есть отправленная — остановка с сообщением «В этом месяце уже есть декларация» и её номером.
   - Есть сохранённая (saved) — расширение показывает её номер и спрашивает подтверждение. «Нет» — остановка.
   - После ответов: Monthly → Small Business Income Declaration, поле «Период» = месяц из даты дохода. Потом открыть сохранённую или нажать New return. На каждом шаге расширение сначала находит элемент, потом нажимает. Не нашло — ошибка и остановка.
6. **Заполнение.** Расширение находит поля 15 и 20 и заполняет их.
7. **Запись в файл.** Только после успешного заполнения расширение записывает доход в JSON-файл года.
8. Пользователь проверяет и отправляет декларацию сам.

Ошибка на шагах 1–5: на RS ничего не создано. Ошибка на шаге 6: на RS может остаться пустой черновик — расширение сообщает об этом.

Порядок шагов проверяют тесты `extension/flow.test.js` (сценарий `extension/flow.js` с заглушками вместо сайта, файла, NBG и панели).

### Месяц без дохода

Сумма USD = 0 означает «нет дохода». Отдельной галочки нет.

- Из даты берётся только месяц декларации.
- Шаг 3 (курс NBG) пропускается.
- Поле 15 = сумма за год из JSON-файла, без изменений. В январе = 0.
- Поле 20 = 0.
- В JSON-файл ничего не записывается.

Остальные шаги и проверки — как в обычном сценарии.

### Первый запуск и прошлые доходы

Поле 15 — сумма за весь год, поэтому в файле должны быть все доходы года до текущего месяца.

На шаге 2, если в файле года нет записи хотя бы за один месяц с января до месяца декларации, расширение называет эти месяцы и спрашивает: «Были доходы в эти месяцы?»

- «Нет» — эти месяцы записываются в файл с суммой 0. Расширение продолжает.
- «Да» — таблица: строка на каждый из этих месяцев. В строке — дата (предзаполнено 22 число этого месяца) и сумма USD. Пустая сумма — 0.
  - «Сохранить и продолжить» — расширение получает курсы NBG, записывает все месяцы в файл и продолжает. Ошибка в любой строке — файл не меняется, таблица остаётся открытой для исправления.
  - «Отмена» — остановка.

Месяц без дохода хранится как запись с суммой 0 на 1 число месяца. После записи прошлых месяцев вопрос и таблица больше не появляются. Записанные месяцы не перезаписываются: доход поверх записи (в том числе с 0) — ошибка.

### Сообщения об ошибках

Каждое сообщение подробное и понятное. В нём:

- **шаг**, на котором остановилось расширение;
- **что ожидалось** и **что найдено** (например: «Не найдена кнопка New return на странице Small business annual income»);
- **что изменено на RS** к этому моменту («ничего» или «создан черновик за сентябрь 2026»);
- **что сделать пользователю** (например: «Залогиньтесь на eservices.rs.ge и нажмите на расширение снова»);
- для ошибок NBG — дата запроса и ответ сервера.

### Поля декларации

Расширение заполняет только два поля. Остальные сайт заполняет сам или оставляет 0.

- **Поле 15** — доход в GEL с начала календарного года, включая текущий месяц.
- **Поле 20** — доход в GEL за этот месяц.

Месяц декларации = месяц даты получения дохода. Расширение проверяет это перед заполнением.

С января накопление начинается с нуля (декларация за январь подаётся в феврале).

### Курс

API NBG:

```
https://nbg.gov.ge/gw/api/ct/monetarypolicy/currencies/en/json/?currencies=USD&date=YYYY-MM-DD
```

Проверено 2026-10-02: API отвечает JSON без авторизации. Берём поле `rate`.

На выходные и понедельник API возвращает курс, действующий на эту дату: курс установлен в пятницу и действует с субботы (`validFromDate`). Пример: на 2026-09-20 и 2026-09-21 вернулся курс 2.6071 с `validFromDate` 2026-09-19.

Страница для ручной проверки: https://nbg.gov.ge/en/monetary-policy/currency

### Хранение

JSON-файлы на диске, один файл на год: `2026.json`, `2027.json`.

Данные хранятся только на компьютере пользователя. Расширение никуда их не отправляет. Наружу уходят только дата в запросе курса к NBG и поля 15 и 20 в форму RS.

Доступ через File System Access API: пользователь один раз выбирает папку на странице расширения. После перезапуска Chrome может запросить подтверждение доступа.

Формат:

```json
{
  "year": 2026,
  "incomes": [
    { "date": "2026-09-21", "usd": 6100.55, "rate": 2.7, "gel": 16471.49, "tax_gel": 164.71 }
  ],
  "total_usd": 19000.00,
  "total_gel": 51300.00
}
```

Числа в примере условные.

Налог = 1% от GEL. Ставка задана в коде. Если ставка изменится — меняем код.

## Последствия

- Если RS изменит страницы, расширение остановится с ошибкой на этом шаге. Нужно будет править селекторы.
- Проверить все селекторы в момент запуска нельзя: элементы следующей страницы появляются только после перехода. Поэтому проверка идёт перед каждым шагом, а необратимое действие (New return) — только после всех проверок.
- Резервную копию папки с данными пользователь делает сам.
- Логин и пароль RS расширение не хранит и не вводит.

## Открытые вопросы

1. Несколько поступлений в одном месяце. Сейчас поддерживается только одно: если в файле уже есть доход за этот месяц с другой датой или суммой — ошибка и остановка. Возможно, позже — суммировать в поле 20.
2. Исправление старых данных: перезаписать доход за записанный месяц (ошибка в сумме или дате, месяц ошибочно записан с 0). Сейчас нельзя — только вручную в JSON-файле. Возможно, позже.
3. Работает ли для расширения вариант «Разрешать при каждом посещении» (File System Access, Chrome 122+)? Проверить на первой версии.
